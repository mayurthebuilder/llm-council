# LLM Council Portfolio v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a secure, provider-neutral, portfolio-grade multi-agent decision engine with blind peer review, deterministic offline tests, a professional CLI, and presentation-ready documentation.

**Architecture:** A typed Python core accepts only explicit user input, calls five advisor roles concurrently through an async provider protocol, anonymizes results for peer review, and asks a chairman to synthesize a structured decision. JSON is canonical; Markdown and safely escaped HTML are renderings. A deterministic fake provider makes the complete flow testable without credentials or network access, while an optional Google Gen AI adapter supplies the first production integration.

**Tech Stack:** Python 3.11+, Pydantic 2, Typer, Rich, asyncio, optional `google-genai`, pytest, pytest-asyncio, pytest-cov, Ruff, mypy, GitHub Actions, Gitleaks.

**Spec:** `docs/superpowers/specs/2026-08-30-llm-council-portfolio-v2-design.md`

## Global Constraints

- Support Python 3.11 and newer.
- Never scan parent directories, home directories, editor state, transcripts, or unrelated workspace files.
- Accept context only from an explicitly supplied UTF-8 file inside the current working directory.
- Never print, serialize, cache, or include provider credentials in errors.
- Keep telemetry and persistent history disabled.
- Treat user context and model output as untrusted text and escape HTML output.
- Use sanitized fictional examples with no personal Gmail address, local user path, session URL, secret, client data, or private identifier.
- Required tests run offline without paid API calls; real-provider smoke tests are optional and manual.
- Do not publish performance, accuracy, provider, or coverage claims that cannot be reproduced from the repository.
